# 📋 사용 범위 안내 — REA로 무엇을 해도 되고, 무엇을 하면 안 되나

> 한 줄 요약: **REA는 범위를 스스로 막지 않습니다. 범위는 사용자가 정하고, 이 툴은 그 범위를 프롬프트에 적어 에이전트에게 전달합니다.**
> 그래서 "어떤 파일을, 무엇을 위해" 분석하는지가 가장 중요합니다.

법률 자문이 아닙니다. 실제 판단은 거주 국가의 법과 각 소프트웨어의 약관(EULA)을 따르세요.
쉬운 비유로 읽고 싶다면 [WHY_GAME_MODDING.md](WHY_GAME_MODDING.md)를 먼저 보세요.

---

## 1. REA가 하는 것과 하지 않는 것

REA 스킬 문서(`.agents/skills/reverse-engineer-anything/`)에 적힌 동작을 사용자 입장에서 정리했습니다.

| REA 문서 내용 | 사용자에게 의미하는 것 |
|---|---|
| REA 도구에는 **권한 부여나 호출마다 승인받는 절차가 없음**. 승인은 에이전트 앱(Claude Code 등)이 따로 요구할 수 있을 뿐 | REA는 "이 파일은 분석하면 안 된다"를 판단하지 않습니다. **범위를 지키는 책임은 사용자와 프롬프트에 있습니다.** |
| 요청에 적힌 **대상과 동작만** 다루고, 그 범위를 넓히지 않음 | 프롬프트에 대상을 정확히 한 개로 적으면 그 밖으로 나가지 않습니다. 이 툴이 대상 파일·작업 폴더를 고정하는 이유입니다. |
| "내 앱"처럼 대상이 불분명하면 **어떤 앱인지 먼저 물어봄**. 예시 앱을 대신 고르지 않음 | 대상을 직접 골라 주세요. 근처 폴더의 다른 파일을 멋대로 분석하지 않습니다. |
| 정적 분석은 **실행하지 않음**. 런타임 관찰은 요청한 대상을 **실제로 실행**함 | 실행이 필요한 단계(에뮬레이터 실행, `npx electron .` 등)는 내 PC에서 그 프로그램이 돌아간다는 뜻입니다. |
| 브라우저·Electron 관찰은 **수동(passive)** 이며, 쿠키·인증 헤더·저장소 값은 **일부러 수집하지 않음** | 로그인 정보나 토큰을 빼내는 용도로는 쓸 수 없고, 쓰려고 해서도 안 됩니다. |
| 결론마다 **확인된 사실 / 추정 / 모르는 것**을 구분 | 결과 보고서의 "추정"은 확인된 사실이 아닙니다. 그대로 믿고 배포하지 마세요. |
| REA 설치는 Node.js·Java·Ghidra 같은 **다른 프로그램을 설치하지 않음** | 필요한 도구는 `bat/download_analysis_tools.bat`이나 환경 점검 안내를 따라 직접 설치합니다. |

## 2. 이 툴이 프롬프트에 넣는 범위 규칙

REA에 범위 장치가 없기 때문에, 이 툴은 모든 프롬프트에 다음을 넣습니다 (`Services/PromptBuilder.cs`의 공통 규칙).

- **대상 고정:** 대상 파일 경로 1개와 전용 작업 폴더
- **원본 보호:** 원본 파일과 설치 폴더는 수정하지 않고, 필요하면 작업 폴더에 복사본을 만듦
- **범위:** 로컬·싱글플레이 분석과 모드 제작만. 온라인 게임의 안티치트/DRM/서버 검증 우회, 결제·재화 조작, 암호화된 바이너리나 메타데이터의 복호화는 하지 않음
- **멈춤 조건:** 같은 오류가 반복되면 우회책을 계속 시도하지 않고 멈춤

> ⚠️ 이 규칙은 **에이전트에게 주는 지시**일 뿐, 기술적으로 막는 장치가 아닙니다. 프롬프트를 고쳐서 규칙을 지우면 막아 주는 것은 없습니다.

## 3. 용도별 안내

EXE · DLL · APK · APP 같은 일반 타겟도 이 툴로 다룰 수 있습니다. 어떤 타겟이든 **기준은 파일 종류가 아니라 목적**입니다.

### ✅ 해도 되는 것

- 내가 구매·소유한 게임의 **싱글플레이 모드** 제작 (Unity IL2CPP · Mono · APK · APP, 일반 EXE/DLL 게임)
- **내가 직접 만든** 프로그램, 오픈소스 프로그램 분석
- 분석 연습용으로 만들어진 **크랙미 · CTF** 문제

### ⚠️ 목적을 분명히 하면 대체로 가능한 것 (구매한 상용 소프트웨어)

- **호환성·상호운용:** 내 데이터 파일 형식 읽기, 플러그인·확장 만들기, 다른 프로그램과 연동
- **문제 해결:** 내 PC에서 생기는 충돌·오류 원인 찾기
- **학습:** 구조를 이해하기 위한 분석 (결과물은 배포하지 않음)

이 경우에는 프롬프트에 **목적·소유 여부·결과물을 어디에 쓰는지**를 적어 주세요. 그리고 결과물(디컴파일 코드, 추출 리소스)은 **내 PC 밖으로 내보내지 마세요.**

### ❌ 하지 않는 것

- 라이선스 확인 · 시리얼 · 체험판 제한 **제거 (크랙)**
- DRM · 안티치트 · 서버 검증 **우회**, 온라인 게임 핵
- 디컴파일한 코드나 원본 리소스를 **재배포**하거나, 그것으로 **비슷한 제품을 만드는 것**
- 다른 사람의 **계정 · 결제 · 개인정보**에 닿는 분석
- 악성코드 제작이나, 남의 시스템을 공격하기 위한 취약점 분석

## 4. 왜 게임 모딩은 비교적 받아들여지고, 상용 소프트웨어는 민감할까

차이는 "게임이냐 아니냐"보다 **목적과 피해 가능성**에서 생깁니다.

- **게임 모딩:** 개발사가 공식 지원하거나 묵인하는 경우가 많고, Nexus Mods · Steam Workshop처럼 오래된 커뮤니티 관행이 있습니다. 결과가 내 PC 안에 머무는 경우가 대부분입니다.
- **상용 소프트웨어:** "구매한 프로그램을 분석해 줘"라는 요청은 라이선스 제거(크랙)로 이어지는 경우가 많아서, 목적이 적혀 있지 않으면 위험한 요청과 구별되지 않습니다.
- **구매했다고 다 되는 것은 아닙니다.** 많은 EULA가 리버싱을 금지합니다. 다만 여러 나라의 법은 **호환성 목적의 역분석**을 조건부로 허용합니다. 예를 들어 한국 저작권법 제101조의4(프로그램코드역분석), EU 소프트웨어 지침 제6조, 미국 DMCA 1201(f)가 있습니다. 공통 조건은 대략 이렇습니다: 정당하게 얻은 프로그램일 것, 호환에 꼭 필요한 부분만 분석할 것, 얻은 정보를 다른 목적에 쓰거나 남에게 주지 않을 것.
- **게임도 예외가 아닙니다.** 게임에서도 DRM·안티치트 우회나 온라인 핵은 똑같이 민감합니다.

그래서 AI 에이전트는 파일 종류보다 **요청에 적힌 목적**을 보고 판단합니다. 목적이 분명한 게임 모딩은 잘 도와주고, 목적 없는 상용 소프트웨어 분석은 조심하거나 거절하는 경향이 보이는 것입니다.

## 5. AI가 거절했을 때

- **거절은 버그가 아니라 정상 동작입니다.** 말을 바꿔 우회하려고 하면 더 의심스러운 요청으로 보입니다.
- 정당한 목적이라면 **목적 · 소유 여부 · 결과물 사용처**를 한두 문장으로 덧붙이세요.
- 그래도 거절된다면 그 작업은 **이 툴의 범위 밖**으로 보고 멈추세요.

프롬프트 맨 위에 덧붙일 목적 문장 예시:

```text
목적: 내가 Steam에서 구매한 <게임 이름>의 싱글플레이 모드(인벤토리 칸 수 늘리기)를 만들려고 해. 결과물은 내 PC에서만 쓰고, 원본 게임 파일이나 디컴파일한 코드는 배포하지 않아.
```

```text
목적: 내가 구매한 <프로그램 이름>이 저장하는 프로젝트 파일(.xyz)을 내가 만드는 변환기에서 읽으려고 해. 파일 형식을 읽는 부분만 분석하고, 라이선스·인증 관련 코드는 다루지 마.
```
